Vue d'ensemble du projet

Compétens est une application web de gestion scolaire destinée aux écoles primaires. Elle permet de suivre la progression des élèves sur un ensemble de compétences comportementales et académiques, à travers des évaluations quotidiennes.

Ce que fait l'application

RôleCe qu'il peut faire
AdminTout gérer : années scolaires, niveaux, classes, élèves, professeurs, compétences, alertes, utilisateurs, demandes en attente
DirecteurVoir les tableaux de bord globaux, consulter les élèves et alertes, accès en lecture étendu
ProfesseurÉvaluer ses élèves quotidiennement, consulter la progression de ses classes, voir les alertes
ParentConsulter en lecture seule la progression de son/ses enfants liés par l'admin

Flux principal

  1. Inscription — Professeur ou parent s'inscrit → compte en attente (status: pending)
  2. Approbation — Admin approuve depuis /admin/pending-teachers → status passe à active
  3. Assignation — Admin (ou professeur via demande) assigne des classes au professeur
  4. Évaluation — Professeur évalue ses élèves chaque jour (Non acquis / En cours / Acquis)
  5. Alertes — Le système génère des alertes pour les élèves en difficulté
  6. Consultation — Admin/directeur voient les statistiques globales, parents voient leurs enfants
💡

Mode démo

L'application possède un mode démo complet avec données fictives (Zustand + localStorage), sans aucune connexion à Supabase. Utile pour présenter l'application sans compte.

🔒

RLS — Row Level Security

Toutes les tables ont RLS activé. Cela signifie que même si quelqu'un obtient la clé anon, il ne peut accéder qu'aux lignes autorisées par sa session. C'est la sécurité au niveau de la base de données, indépendante du code frontend.

Trigger important

La fonction handle_new_user() s'exécute automatiquement après chaque inscription Supabase Auth. Elle crée la ligne dans profiles avec status = 'pending' pour les professeurs. Le code frontend utilise ensuite upsert pour s'assurer que le statut est bien 'pending' même si le trigger a déjà créé la ligne.

Déploiement actuel — GitHub + Vercel (gratuit)

Comment ça fonctionne

📁 Local → git push → 🐙 GitHub → webhook automatique → ▲ Vercel → build + deploy → 🌐 URL publique
  1. Code poussé sur GitHub (branche main) — Vercel détecte le push automatiquement via un webhook.
  2. Vercel lance le build — Exécute npm run build (Vite compile TypeScript + React → fichiers HTML/JS/CSS statiques dans dist/).
  3. Déploiement sur CDN Vercel — Les fichiers statiques sont distribués sur le réseau mondial de Vercel. URL comme competens-app.vercel.app.
  4. Variables d'environnement — Les clés Supabase sont stockées dans les Settings Vercel (pas dans le code), et injectées lors du build.

Acheter un domaine & déployer dessus

Actuellement l'URL est competens-app.vercel.app. Pour avoir une URL professionnelle comme competens.ma ou monecole.fr, voici la procédure complète :

Étape 1 — Acheter le domaine

Choisir un registrar (vendeur de domaines) :

RegistrarPrix indicatif (.com)Notes
Namecheap~10$/anInterface simple, recommandé pour débutants
GoDaddy~12$/anTrès connu, interface parfois complexe
Porkbun~9$/anMoins cher, excellent rapport qualité/prix
OVH~8€/anHébergeur européen, bon pour .fr .ma
Gandi~16€/anFrançais, respectueux des données

Étape 2 — Lier le domaine à Vercel

  1. Dans Vercel → Dashboard → votre projet → Settings → Domains → Add Domain → saisir mondomaine.com
  2. Vercel affiche deux enregistrements DNS à configurer :
    - Un enregistrement A pointant vers l'IP Vercel (ex: 76.76.21.21)
    - Un enregistrement CNAME pour www pointant vers cname.vercel-dns.com
  3. Chez votre registrar → DNS Management → ajouter ces deux enregistrements
  4. Attendre la propagation DNS : 15 minutes à 48 heures selon les registrars
  5. Vercel active le certificat HTTPS automatiquement (via Let's Encrypt, gratuit)
✅

Résultat

Votre application est accessible sur https://mondomaine.com avec HTTPS, sans rien changer au code. Vercel reste l'hébergeur du frontend, et Supabase reste la base de données. Le domaine est juste un alias.

Si vous voulez tout contrôler (et ne pas dépendre de Vercel), vous pouvez louer un VPS (serveur virtuel privé) :

Alternatives à Supabase (serveur local ou autre)

Option A — Garder Supabase (recommandé)

Supabase est gratuit jusqu'à 500 MB de données et 50 000 utilisateurs auth. Pour une école, c'est largement suffisant. Le plan Pro (~25$/mois) donne 8 GB et des sauvegardes automatiques.

Option B — Pocketbase (serveur local ultra-simple)

PocketBase est un seul fichier exécutable qui inclut base de données SQLite + API REST + Auth + UI admin. Idéal pour un serveur local dans l'école.

# Télécharger pocketbase (Linux/Mac/Windows)
# https://pocketbase.io/docs/

# Lancer le serveur
./pocketbase serve --http=0.0.0.0:8090

# Interface admin accessible sur :
# http://localhost:8090/_/

Pour connecter le frontend React à PocketBase, remplacer Supabase par le SDK PocketBase :

npm install pocketbase

// lib/pocketbase.ts
import PocketBase from 'pocketbase';
export const pb = new PocketBase('http://localhost:8090');
⚠️

Effort de migration

Passer de Supabase à PocketBase nécessite de réécrire tous les hooks (use-students.ts, use-classes.ts, etc.) pour utiliser l'API PocketBase. Les tables SQL doivent être recréées via l'UI admin de PocketBase. Compter 2 à 4 jours de travail.

Option C — Node.js + Express + PostgreSQL local

Solution la plus flexible mais la plus complexe. Requiert de créer une API REST complète, gérer l'authentification JWT manuellement, et administrer PostgreSQL.

# Stack nécessaire
Node.js + Express (API)
PostgreSQL (base de données)
JWT (authentification)
Prisma ou Drizzle (ORM)

# Structure
server/
├── routes/students.ts
├── routes/evaluations.ts
├── middleware/auth.ts
└── db/prisma.schema

Non recommandé pour commencer — Supabase fait tout cela automatiquement.

Option D — Firebase (Google)

Alternative à Supabase, également gratuite dans les limites de base. Utilise Firestore (base NoSQL) au lieu de PostgreSQL. L'authentification est excellente. Moins adapté pour des requêtes SQL complexes comme les statistiques d'évaluations.

Améliorations recommandées

🔴 Priorité haute

  • Génération automatique des alertes — Actuellement les alertes sont créées manuellement ou via du code métier basique. Il faudrait une fonction Supabase (Edge Function ou cron) qui analyse les évaluations et crée automatiquement des alertes quand un élève a plus de 3 évaluations "non_acquis" sur 2 semaines.
  • Tests unitaires — Vitest est installé mais aucun test n'est écrit. Il faut tester au minimum les hooks (use-evaluation, use-student-detail) et la logique de calcul des taux d'acquisition.
  • Protection des routes par rôle — Actuellement la navigation menu filtre par rôle, mais une URL tapée directement (/school-years par un professeur) n'est pas bloquée au niveau du routing. Ajouter un composant ProtectedRoute.

🟡 Priorité moyenne

  • Pagination des listes — Students, Evaluations : si l'école a 500+ élèves, les requêtes Supabase sans limite peuvent être lentes. Ajouter .range(0, 49) et une pagination UI.
  • Export PDF des rapports élèves — Les parents/directeurs voudraient pouvoir imprimer le profil d'un élève. Utiliser la librairie jspdf ou @react-pdf/renderer.
  • Notifications en temps réel — Supabase supporte les Realtime subscriptions. Les alertes pourraient apparaître immédiatement sans recharger la page.
  • Réinitialisation du mot de passe — Actuellement l'admin doit manuellement réinitialiser. Supabase Auth supporte nativement l'email de reset (supabase.auth.resetPasswordForEmail()).
  • Photo de profil élève — Le champ photo_url existe dans la table students mais n'est pas utilisé dans l'UI. Ajouter un upload vers Supabase Storage.

🟢 Priorité basse

  • Internationalisation (i18n) — L'interface est entièrement en français. Ajouter react-i18next pour supporter l'arabe ou d'autres langues.
  • Application mobile native — Le projet peut être converti en app React Native (Expo) en réutilisant les hooks et la logique Supabase. Seul l'UI change.
  • Historique des évaluations — Afficher l'évolution d'un élève dans le temps avec un graphique linéaire (LineChart Recharts).
  • Dark mode persistant — Le dark mode existe déjà mais est stocké en localStorage. Le centraliser dans les préférences utilisateur Supabase.

Conseil pour le nouveau développeur

Commencez par lire App.tsx (les routes), puis types/index.ts (les interfaces), puis un hook simple comme use-levels.ts. Une fois que vous comprenez le patron démo/réel, vous pouvez lire tous les autres hooks. Ne touchez pas à app-store.ts ni à AppLayout.tsx avant d'avoir bien compris la structure globale.
